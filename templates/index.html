🎯 Regularization Rationale

Lasso (L1) imposes an absolute-value penalty driving 49% of regression coefficients to exactly 0, performing embedded feature selection. Ridge (L2) shrinks weights smoothly, handling multicollinearity between weather factors.

⚖️ Bias-Variance Tradeoff

OLS has minimum training bias but is vulnerable to sample noise. Introducing regularization parameter α introduces slight bias to dramatically compress variance, preventing test-time overfitting.

📏 Feature Scaling Necessity

Without StandardScaler, variables with large units (e.g., Pressure ~30, Temperature ~80) dominate penalization over tiny variables (Precipitation ~0.1). Scaling guarantees uniform geometric shrinkage.

Ensemble Theory: Bagging vs. Boosting

Random Forest (Bagging): Combines 100 deep, unpruned trees trained on bootstrap resamples with random feature subsets. By decorrelating trees (ρ ↓), ensemble variance σ2/B reduces without affecting bias.


Boosting (XGBoost & LightGBM): Fits trees iteratively along the negative gradient of the multi-class log-loss function: −∇ L(y, F(x)). Each new tree corrects the residual errors of prior trees, systematically driving down model bias.

🏬 Feature Store Design

Cataloged in data/feature_store.json. Stores canonical entity schemas, historical feature medians, categorical vocabularies, and temporal derivation rules.

  • Offline Store: Historical 80,000 incident sample profiles
  • Online Store: Low-latency default imputation for live HTTP requests
  • Schema Validation: Rejects out-of-bounds geographic or temporal inputs
⚙️ Training-Serving Skew Avoidance

The exact same ColumnTransformer object used during offline training is serialized via joblib and loaded into the REST inference handler.

  • Zero Data Leakage: Scalers fit solely on training partitions
  • Identical Encoding: OneHotEncoder maps categorical values uniformly
  • Handling Unknowns: Unseen categories mapped to zero-vector
